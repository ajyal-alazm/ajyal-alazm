# موقع أكاديمية أجيال العزم لكرة القدم — نسخة Supabase

واجهة عربية RTL متجاوبة متصلة بمشروع Supabase الخاص بالأكاديمية. تستخدم الواجهة `Project URL` ومفتاح `Publishable` فقط؛ لا تضع `Secret` أو `service_role` في ملفات الموقع.

## الميزات
- البحث عن اللاعبين وتصفيتهم حسب الفئة والفرع.
- ملفات اللاعبين، مراكز اللعب، سنة الميلاد، التقييمات الشهرية، مخطط التطور وألبوم الصور.
- دخول مسؤول باستخدام Supabase Auth (البريد وكلمة المرور، وليس كلمة مرور محلية).
- إضافة/تعديل/حذف اللاعبين، رفع صورة أساسية وصور الألبوم من الجهاز، وإدارة التقييمات الشهرية.
- التخزين المشترك في قاعدة بيانات Supabase بدل `localStorage`.

## خطوات الربط (مشروعك تم إنشاؤه بالفعل)
1. افتح مشروع Supabase: `https://supabase.com/dashboard/project/mulodqwjslfyapgupbgw`.
2. تأكد أن SQL الخاص بالجداول والسياسات قد نُفّذ وأن صف حساب المسؤول موجود في `public.profiles` مع `role = 'admin'`.
3. افتح **SQL Editor → New query**، وانسخ محتوى `storage_setup.sql` وشغّله مرة واحدة. سيجهّز bucket باسم `player-images` وسياسات رفع الصور للمسؤول.
4. نزّل هذا الملف ZIP وفك ضغطه.
5. افتح `index.html` للتجربة. يتطلب الاتصال بالإنترنت لتحميل Supabase JS والخط. إذا منع المتصفح طلبات الشبكة من `file://`، افتح الموقع من GitHub Pages أو خادم محلي.
6. اضغط «دخول الإدارة» واستخدم البريد وكلمة المرور لحساب Supabase الذي أنشأته. لا تنشئ كلمة مرور محلية.
7. أضف لاعبًا تجريبيًا غير منشور أولًا، وارفع صورة، وسجّل تقييمًا؛ تحقق من ظهور الصفوف في Table Editor. بعد الاختبار، انشر فقط الملفات والصور التي توجد موافقة ولي الأمر على نشرها.

## تحديث موقع GitHub Pages الموجود لديك
- افتح مستودع GitHub `ajyal-alazm/ajyal-alazm`.
- استبدل `index.html` الموجود بالنسخة الموجودة داخل هذا المجلد (Upload files أو Edit file)، ثم Commit changes.
- قد يستغرق تحديث GitHub Pages بضع دقائق. افتح موقعك وجرّب تسجيل دخول المسؤول.
- ارفع `storage_setup.sql` إلى جهازك وافتح محتواه في SQL Editor؛ لا تحتاج إلى إعادة إنشاء الجداول إذا كانت قد أُنشئت بالفعل.

## إعدادات الاتصال الموجودة في index.html
- Project URL: `https://mulodqwjslfyapgupbgw.supabase.co`
- Publishable key: يبدأ بـ `sb_publishable_` ومضمّن في الواجهة. هذا المفتاح عام بطبيعته؛ أمان البيانات يعتمد على RLS وسياسات التخزين.

## ملاحظات أمان مهمة
- لا تضف إلى الملفات العامة عنوان الطفل أو هاتفه أو مدرسته أو معلومات صحية أو ملاحظات داخلية.
- هذه الواجهة تعرض التقييمات الرياضية للاعبين المنشورين. راجع سياسات RLS الحالية قبل استخدام بيانات حقيقية.
- الصور في bucket عام حتى تظهر للزوار؛ لذلك أي شخص يملك رابط الصورة يمكنه مشاهدتها. انشر صورًا بموافقة ولي الأمر فقط.
- لا تضع أبدًا `sb_secret_...` أو `service_role` في HTML أو GitHub.
- إذا تغيّرت أسماء أعمدة الجداول أو سياسات RLS لديك عن SQL الذي أعددناه، فقد تحتاج الواجهة إلى تعديل لتطابق المخطط الفعلي.
